# Asta Bot

**منصة SaaS لتشغيل بوتات واتساب**: كل مستخدم يسجّل حسابًا، يربط رقمه بكود واحد، ثم يدير بوته وأوامره وإحصائياته ويصمّم هوية بوته من لوحة تحكم واحدة بتصميم أزرق حديث.

| | |
|---|---|
| **المنصة** | Node.js ‏`>= 18` · ES Modules |
| **اتصال واتساب** | `@whiskeysockets/baileys` |
| **الواجهة** | HTML + CSS + JavaScript خالص (بدون إطار عمل) |
| **التصميم** | Midnight Blue · RTL أولًا · ثيم داكن وفاتح · عربي وإنجليزي |

## نظرة عامة

Asta Bot يعمل بمعمارية **Supervisor + Workers**:

- **Supervisor** (`index.js`) يدير الحسابات ويشغّل لكل حساب عملية **Worker** مستقلة (`main.js`).
- **لوحة تحكم مركزية واحدة** (`dashboard/server.js`) تخدم الجميع، وتتحدث مع الـ Supervisor عبر قناة تحكم محلية.
- **كل مستخدم = حساب بوت واحد**، بياناته وجلساته معزولة عن باقي الحسابات.

دليل المستخدم النهائي وقائمة الأوامر الكاملة موجودان في [`dashboard/public/README.md`](dashboard/public/README.md)، وهو الملف الذي تعرضه صفحة الدخول.

## لوحة التحكم

التصميم **Midnight Blue**: خلفية زرقاء ليلية بتدرجات، توهج نيون أزرق متوازن، وسطوح زجاجية (Glassmorphism) في الشريط الجانبي والشريط العلوي وبطاقة الدخول.

### مكونات الواجهة

| المكوّن | الوصف |
|---|---|
| **الشريط الجانبي** | أقسام مجمّعة بأيقونات، تمييز الصفحة الحالية بمؤشر مضيء، **تصغير وتوسيع** مع حفظ الاختيار، بطاقة البوت المحدد بهويته وحالته، وبطاقة المستخدم أسفله |
| **الشريط العلوي** | مسار الصفحة (Breadcrumbs) وعنوانها، حالة الاتصال، مبدّل الحساب، الثيم، اللغة، الإشعارات، وقائمة الحساب |
| **الموبايل** | الشريط الجانبي يتحول لقائمة منزلقة تُفتح بزر القائمة وتُغلق عند التنقل أو بزر `Esc` |
| **البطاقات والجداول** | بطاقات إحصائيات بأيقونات، جداول بتمرير أفقي داخلي، وشارات حالة ملوّنة |
| **النوافذ والقوائم** | نوافذ منبثقة وقوائم منسدلة وإشعارات Toast بحركات ناعمة |
| **حالات الواجهة** | هياكل تحميل (Skeletons)، حالات فارغة، رسائل نجاح وخطأ، وشريط انقطاع الاتصال |

الحركات تحترم إعداد النظام `prefers-reduced-motion`.

### نظام الأيقونات

ملف واحد `dashboard/public/icons.js` يوفّر مجموعة أيقونات خطية موحدة (91 أيقونة بنفس السماكة والأبعاد) عبر `AstaIcons.svg(name)`، وتستخدمه كل الصفحات. المجموعة مكتوبة داخل المشروع وبدون أي مكتبة خارجية.

### زر إظهار وإخفاء كلمة المرور

الملف `dashboard/public/password-toggle.js` يضيف زر العين تلقائيًا لكل حقل `input[type=password]`، **بما فيها الحقول التي تُنشأ لاحقًا** داخل النوافذ والصفحات الديناميكية.

- يبدّل النوع بين `password` و`text` دون المساس بالقيمة أو بإرسال النموذج.
- يبدّل شكل الأيقونة، ويعمل بلوحة المفاتيح (`Enter` و`Space`)، ويعلن حالته عبر `aria-pressed` و`aria-label`.
- يعيد إخفاء الكلمة تلقائيًا عند إرسال النموذج.
- يُستثنى أي حقل داخل عنصر يحمل الخاصية `data-no-pw-toggle`.

## الحسابات والأدوار والصلاحيات

| الدور | المستوى | الصلاحيات |
|---|---|---|
| `owner` | مطور | كل الصلاحيات |
| `admin` | مطور | كل الصلاحيات |
| `manager` | مدير | كل الصلاحيات عدا `commands.manage`؛ يدير المستخدمين العاديين والمعلّقين والمشاهدين فقط، ولا يعيّن إلا دور `user` |
| `viewer` | مشاهد | `stats.view` فقط |
| `pending` | معلّق | بلا صلاحيات حتى يكتمل تجهيز الحساب |
| `user` | مستخدم | التحكم في بوته الخاص فقط عبر `/my` |

المستخدم بدور `user` لا يصل إلا لمسارات `/api/my/*` و`/api/account/*`، ويُرفض أي طلب آخر في الـ Backend. ملكية البوت تُتحقق من الخادم في كل طلب، ولا يُعتمد أبدًا على معرّف حساب يرسله المتصفح.

## هوية البوت

كل مستخدم يخصّص هوية بوته من الصفحة `/my/identity` (**Bot Appearance & Identity**).

### ما الذي يمكن تخصيصه

| العنصر | التفاصيل |
|---|---|
| **الاسم** | من 2 إلى 32 حرفًا، تُرفض المحارف غير المرئية والتحكمية، وترك الحقل فارغًا يعيد الاسم الافتراضي |
| **الصورة** | إحدى ثلاث: أيقونة جاهزة (16 أيقونة)، أو إيموجي واحد، أو صورة من الجهاز (PNG / JPEG / WebP حتى 512 كيلوبايت وبين 32 و4096 بكسل) |
| **اللون واللون المميز** | من 8 درجات زرقاء ثابتة |
| **الشكل** | دائري، مستدير الحواف، ناعم، سداسي |
| **الإطار** | بدون، حلقة، توهج، تدرج |

الصفحة تعرض **بطاقة معاينة** تتغير مباشرة أثناء التعديل، بما فيها مظهر البوت في الشريط الجانبي وفي قائمة البوتات. الصورة لا تُرفع إلا عند الضغط على **حفظ التغييرات**، وأي مسودة غير محفوظة تبقى عند التنقل بين الصفحات مع تنبيه بوجود تعديلات لم تُحفظ. زر **استعادة الافتراضي** يحذف الاسم والصورة والألوان.

### أين تظهر الهوية

الشريط الجانبي (للمستخدم وللمطور عند اختيار الحساب)، الصفحة الرئيسية، رأس كل صفحة في لوحة المستخدم، صفحة الحسابات، جدول الحسابات في نظرة عامة، ومبدّل الحساب. تتحدث الواجهة فور الحفظ دون إعادة تحميل.

### التخزين

بيانات الهوية **مستقلة** عن بيانات الحساب والجلسة:

| المسار داخل مجلد بيانات اللوحة | المحتوى |
|---|---|
| `bot-identities.json` | سجل الهوية لكل `accountId` (الاسم، الألوان، الشكل، الإطار، نسخة الصورة) |
| `identity-avatars/<accountId>.<ext>` | ملف الصورة المرفوعة |

تغيير الهوية **لا يلمس** رقم واتساب ولا بيانات الاتصال ولا جلسة البوت ولا بيانات المصادقة. عند حذف حساب يُحذف سجل هويته وصورته.

### واجهة الـ API

| الطريقة | المسار | الوظيفة |
|---|---|---|
| `GET` | `/api/my/identity` | الهوية الحالية وخيارات التخصيص |
| `PUT` | `/api/my/identity` | حفظ الاسم والمظهر |
| `POST` | `/api/my/identity/avatar` | رفع صورة (`{ "data": "<base64 أو data URL>" }`) |
| `GET` | `/api/my/identity/avatar` | جلب الصورة |
| `DELETE` | `/api/my/identity/avatar` | حذف الصورة |
| `POST` | `/api/my/identity/reset` | استعادة الافتراضي |
| `GET` | `/api/identity/avatar/:accountId` | صورة أي حساب للمطور فقط (`accounts.view`) |

### الأمان في هوية البوت

- **معرّف الحساب يُستخرج من الخادم** من المستخدم المسجّل، ولا يُقرأ من الطلب. أي حقل غير معروف (مثل `accountId` أو `ownerUserId`) يُرفض.
- التحقق من ملكية البوت يتم في الـ Backend قبل أي قراءة أو كتابة.
- كل التعديلات تتطلب رمز **CSRF**، ولها حدود معدل مستقلة.
- الصور تُفحص بـ **توقيع الملف الفعلي** (لا بالامتداد ولا بنوع MIME القادم من المتصفح)، ويُرفض SVG وأي نوع آخر، وتُتحقق الأبعاد والحجم.
- الصورة تُقدَّم بـ `X-Content-Type-Options: nosniff` وسياسة `Content-Security-Policy` مقيّدة وترويسة `ETag`.
- معرّفات الحسابات تُتحقق بنمط صارم قبل تكوين أي مسار ملف، فلا يمكن الخروج من مجلد البيانات.

## تسجيل الدخول وإدارة الحساب

صفحة الدخول مقسومة إلى لوحة تعريفية زرقاء متحركة وبطاقة زجاجية للدخول وإنشاء الحساب، مع رسائل خطأ مصممة، ومؤشر قوة كلمة المرور عند التسجيل، وزر العين في كل حقل كلمة مرور.

| الإجراء | أين؟ |
|---|---|
| تسجيل الدخول وإنشاء حساب | `/login` |
| نسيت كلمة السر / إبلاغ عن مشكلة | روابط أسفل بطاقة الدخول |
| تغيير كلمة المرور وإدارة الجلسات | `/my/account` للمستخدم، و`/account` للإدارة |
| حذف الحساب (مع حذف البوت وبياناته) | `/my/account` |

بعد الدخول يعود المستخدم إلى الصفحة التي كان فيها، بشرط أن تكون مسارًا محليًا آمنًا.

## طريقة الاستخدام

1. أنشئ حسابًا من تبويب **حساب جديد**؛ يُجهَّز البوت تلقائيًا.
2. افتح **واتساب** من القائمة، واكتب رقمك **بكود الدولة وبدون `+`** (مثال: `201012345678`).
3. أدخل الكود الظاهر في واتساب: **الأجهزة المرتبطة ← ربط جهاز ← الربط برقم الهاتف**.
4. خصّص بوتك من **هوية البوت**.
5. أضف البوت إلى مجموعة واكتب فيها `.on` لتفعيله (مرة واحدة لكل مجموعة).

قائمة الأوامر والرتب وشرح كل فئة في [`dashboard/public/README.md`](dashboard/public/README.md).

> ⚠️ البوتات تعمل عبر واتساب ويب (طريقة غير رسمية)، وقد يقيّد واتساب الأرقام التي تُستخدم بشكل مزعج. يُفضّل التجربة على رقم ثانٍ.

## التثبيت والتشغيل

**المتطلبات:** Node.js ‏18 أو أحدث، وللتحويلات الوسائطية `ffmpeg` متاح في `PATH`.

```bash
npm install
```

أنشئ ملف `.env` في جذر المشروع (القائمة الكاملة في [`docs/ENVIRONMENT.md`](docs/ENVIRONMENT.md)). الحد الأدنى لتشغيل اللوحة:

```bash
DASHBOARD_ENABLED=true
DASHBOARD_HOST=127.0.0.1
DASHBOARD_PORT=3000
DASHBOARD_ADMIN_USER=admin
DASHBOARD_ADMIN_PASSWORD=ضع-كلمة-مرور-قوية
```

التشغيل:

```bash
npm start
```

ثم افتح `http://127.0.0.1:3000/login`.

### التشغيل على سيرفر

| الطريقة | الملف |
|---|---|
| PM2 | `pm2 start ecosystem.config.cjs --env production` |
| systemd | انسخ `deploy/asta-bot.service` وعدّل `User` و`WorkingDirectory` ثم `systemctl enable --now asta-bot` |
| Caddy / Nginx | `deploy/Caddyfile.example` و`deploy/nginx.conf.example` |

استخدم طريقة واحدة فقط (PM2 أو systemd)، ولا تشغّل البوت بصلاحيات root.

### تحديث تصميم اللوحة

كل ملفات الواجهة داخل `dashboard/public/` وتُخدم مباشرة، فلا توجد خطوة بناء. بعد استبدال الملفات أعد تشغيل العملية لتحميل `dashboard/server.js` و`dashboard/lib/*` المحدّثة، ثم حدّث الصفحة بـ `Ctrl+Shift+R`.

## الاختبارات

```bash
npm test                  # كل الاختبارات
npm run test:identity     # هوية البوت: التخزين، الصور، العزل، الصلاحيات
npm run test:design       # نظام التصميم: الألوان والتباين وخلو الكود من التعليقات
npm run test:shell        # شل لوحة الإدارة
```

اختبارات المتصفح (`*.browser.test.mjs`) تحتاج Playwright وChromium، وتتخطّى نفسها تلقائيًا إن لم يتوفرا.

`test:identity` يغطي: التحقق من الاسم والإيموجي والألوان، رفض الحقول غير المعروفة، فحص توقيع الصور (نوع وحجم وأبعاد وتلف)، رفض SVG وHTML، الحماية من الخروج من مجلد البيانات، عزل هوية كل حساب، ومنع مستخدم من تعديل بوت غيره (`403`)، وإلزامية CSRF.

## الأمان

- مصادقة بجلسات وCSRF، وحدود معدل لكل نوع إجراء، وقفل مؤقت بعد محاولات الدخول الفاشلة.
- عزل بيانات الحسابات وفصل صلاحيات المستخدم عن الإدارة في الـ Backend.
- سجل تدقيق للإجراءات الحساسة، وتسجيل محاولات الوصول لحساب غير مملوك.
- لا تُرفع ملفات `.env` أو الجلسات أو `accounts/` أو `database/`.
- تفاصيل أكثر في [`SECURITY.md`](SECURITY.md) و[`docs/INSTALL_SECURITY.md`](docs/INSTALL_SECURITY.md).
